# Image: 生图工作流

用户想生成或修改图片。你的职责：把用户的提示词**原样**交给 `ImageGenerate`（内容完全以用户为主、不作发挥），只处理参数类事项（模式 / 尺寸 等），最后把图片路径交给用户。

## 第一步：直接进入工作流（不要为检查配置单独调用）

不要为了"测试配置"而发起一次 `ImageGenerate`——配置正常时那会真的生成一张废图、白花额度。
正确顺序：**先完成第二、三步的模式判定与 prompt 准备，再发起真实的生成调用。**

如果真实调用返回"未配置"错误：

1. 回复用户：「生图 API 尚未配置，请输入 `/config image` 完成配置（选服务商 → 填 URL → 填 APIKey → 填模型）。配置完成后告诉我，我会**自动继续**刚才的请求。」
2. **不要**询问、索要、或接受 APIKey —— 密钥只走 `/config image` 的本地对话框，绝不进入对话。
3. 用户说配置完成后，直接重试生图，**让用户重述需求**是失败的体验。

## 第二步：判定模式

| 情形 | mode | 参数 |
|---|---|---|
| 纯文字要一张新图 | `new` | 用户的 prompt（内容零发挥，见第三步） |
| 用户消息带了图片附件，要改它 | `edit` | `imagePaths: [附件路径]` |
| "继续改上一张 / 再改改" | `continue` | 用会话里上一张输出 |
| 说要"改"但上下文没有图 | **先问图** | 请用户发图或给文件路径，不要瞎猜 |

- 附件路径以消息中实际出现的文件路径为准；拿不到路径就向用户要。
- 路径规则与 Read 相同：**敏感文件（密钥/凭证/env）会被工具直接拒绝**，相对路径不得逃出工作区——遇到这类报错就告诉用户换一张图，不要绕过工具。
- 想出多张变体：同一 `session` 连续调用多次 `new`，prompt 每次换一个变体方向。

## 第三步：prompt 以用户为主（内容零发挥）

生图模型自己就懂提示词——**不要替用户加工**：

1. **原样直传**：用户给什么就输入什么；用户给了详细提示词就**一字不改**，不加主体细节、不加风格 / 光照 / 构图。
2. **最多微微调**：仅修明显的笔误 / 病句，不碰元素与语义。
3. **含糊也直传**："画一只猫" 就输入 `画一只猫`——品种、场景、风格由模型自行诠释，不要替用户补全。
4. **用户明确要求优化时**才优化，按其要求来；skill 不主动代劳、不主动加料。

**参数类才是你要优化的**——尺寸 / 比例、mode 等；用户没提就留空用默认，不瞎猜。

**常用比例 → size 建议**（模型不支持的档位会被自动降级兜底，无需你重试）：

| 用途 | 比例 | size |
|---|---|---|
| 头像 / 图标 | 1:1 | `1024x1024` |
| 壁纸 / 横版插画 | 16:9 | `1536x1024`（竖版反向 `1024x1536`） |
| 海报 / 人像 | 3:4 | `1024x1536` |
| 不确定 / 用户没提 | — | **不传**（留空最安全，服务端会用默认档） |

**带文字的物料（海报等）：文字交给模型**——把用户给的**全部文案写进提示词**（一字不改），由模型完成排版与生成；**禁止**"先生成底图、再用任何工具加字 / 合成 / 后处理"。用户没给文案就先向用户要，不要自己编。

**改图（edit / continue）：同样不套模板**——直接把用户原话作为 prompt、附上图片即可；不要添加用户没说的约束。

示例：
- 用户："画一只猫" → prompt 就是 `画一只猫`（品种 / 场景 / 风格由模型自行诠释）
- 用户："做一张竖版海报，主标题『春日特惠』，副标题『全场五折』，暖色调" → prompt 包含上述原文与全部文案，**一次生成**；不要先生成底图再加字
- 用户（对上一张图）："改成夜景" → prompt 就是 `改成夜景` + 附图

## 第四步：调用与产出

1. 调 `ImageGenerate`：prompt 用**用户的提示词**（内容零发挥）、正确的 mode、按需的尺寸参数，必要时指定 `session`。
2. 成功后向用户展示：**图片绝对路径**；如参数层有可说明的（尺寸等）就顺带一句，**不要汇报"我加工 / 优化了什么"**。建议用户用图片查看能力打开确认。
3. 失败（网络/HTTP/无图数据）：把错误要点转述给用户，给出「换个时段 / 检查 `/config image` 的 URL 与模型」两类排查方向，不要重复粘贴原始堆栈。

## 安全红线

- **永远不要**在回复、日志、示例里回显 APIKey；工具结果里也不会出现它。
- 用户在聊天里粘贴密钥：拒绝使用，引导其 `/config image` 重新输入，并建议他作废已泄露的 key。
- 不要绕过 `ImageGenerate` 用 Bash 直接 curl 生图接口 —— 那会把密钥暴露给 shell 历史与输出。
