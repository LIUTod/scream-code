# Dream: 整理与提炼记忆

用户调用了 `/dream`。记忆库是**全局**的，所有会话的备忘都在同一个 SQLite 数据库里（`<screamHomeDir>/memory/memos.sqlite`）。

记忆库里只有**一种条目**：memo。每条 memo 有需求、方案、踩坑点、经验，以及一个「最新归纳」字段（`distilled`）。`/dream` 的职责是：把散落、重复的经历合并成更少、更清楚的条目，并为合并结果写下一句可复用的结论。

**不是简单删几条。** 单纯的增删等于丢信息；每一次合并都必须产出一句新的「最新归纳」。

## 第一步：取计划

调用 `MemoryConsolidatePlan`。返回：

- `duplicateGroups`：近重复组。每组有 `memos`（原始条目）、`merged`（工具给的合并初稿，`distilled` 为空，等你写）、`reason`。
- `relatedGroups`：主题相关但不算重复的组。默认不合并，仅用于判断是否值得提炼。
- `resolved`：已完成且超过 7 天的条目。
- `stale`：超过 30 天且未完成的条目。
- `summary`：总数、各组数量、整理后条数。

规则：

- `summary.totalMemos === 0` → 回复"记忆库为空，无需整理"，结束。
- 没有任何组和待删除项 → 回复"没有需要整理的记忆"，结束。

## 第二步：展示计划

用 `AskUserQuestion` 让用户选择：`执行整理` / `仅看计划` / `取消`。

展示格式：

```
## Dream 整理计划

### 概况
- 当前记忆：X 条
- 待合并：N 组（涉及 M 条）
- 待删除：R 条

### 待合并
1. <主题> — 4 条 · 2026-08-02 ~ 2026-09-18
   来源构成：3 条经历 / 1 条既有结论
   既有结论：<该组 origin='dream'|'user' 条目原有的 distilled；没有则写「无」>
   最新归纳：<你写的一句话结论>
2. ...

### 相关但保留
- <主题> — 3 条（不合并，仅提炼参考）

### 待删除
- 已完成：A 条
- 已过时：B 条

⚠ 合并后原始条目将被删除，且不可恢复。
```

预览里的「最新归纳」必须是你真正写出来的结论，不能写"待定"。来源构成与既有结论必须来自计划数据，不得省略或编造。

## 第三步：写提炼结果

对每个 `duplicateGroups`，重写 `merged`：

- `userNeed`：这组经历共同解决的需求
- `approach`：最终有效的做法
- `outcome`：结果（完成 / 部分完成 / 失败）
- `whatFailed`：仍然成立的踩坑点；没有就 `none`
- `whatWorked`：仍然成立的经验；没有就 `none`
- `distilled`：**最新归纳**，一句话规则，≤60 字，能直接照着做；不是任务复述

`relatedGroups` 默认不动。只有当你确信整组指向**同一条规则**时，才把它提升为合并组：把它的 memo 放入 `duplicateGroups` 并写好 `merged`（含 `distilled`）。拿不准就保留。

组内包含 `origin='dream'` 或 `origin='user'` 的条目时（其 `distilled` 非空），预览必须展示它原有的 `distilled`，并说明新结论是**继承、修正还是取代**它。既有的规则不会被保留，覆盖是不可逆的。

归纳不出可靠结论的组：跳过，不要为凑数写空话。

## 第四步：执行并报告

把确认后的计划传给 `MemoryConsolidateApply`。工具会：

- 为每个合并组先写入一条新 memo（含「最新归纳」、来源快照与归纳时间），再删除原始条目
- 删除 `resolved` / `stale`
- 返回 `deleted` / `created`

报告：

```
合并 N 组，删除 X 条，新增 Y 条（原始条目已删除，不可恢复）
其中 Z 条带最新归纳
当前：记忆 M 条
```

## 硬性规则

- 只删已经合并进新条目的原料；没有产出结论的组，一条都不能动
- 不得在未展示既有结论的情况下覆盖一条规则；覆盖意味着旧结论永久消失
- `distilled` 必须是可复用结论，不是"整理完成"之类的空话
- 不编造内容：`whatFailed` / `whatWorked` 只能来自原始条目
- 不手改数据库，一切走 `MemoryConsolidateApply`
- 操作前必须得到用户确认
