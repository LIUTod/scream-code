# scream-code

## 0.20.0

### Minor Changes

- [`151b05d`](https://github.com/LIUTod/scream-code/commit/151b05d4f6feb4c316eb367fa546b6d4826ced79) - A fired scheduled task now also surfaces on the status row above the editor, not only as a transcript block. The chip follows the shared grammar: `⏰ 定时任务已触发：<preview>` — with `（合并 N 次）` when several fires collapsed into one delivery, `⏰ 一次性提醒已触发：…` for a one-shot task, and `⚠️ 定时任务已过期，仍触发：…` in the warning colour for a task past its 7-day cutoff. The prompt preview is sanitized and capped at 40 characters because it is model-authored text written into a terminal row. The reminder owns its own slot (10s TTL) drawn to the left of the collaboration ticker (8s), so a help request can neither evict a fired reminder nor outlive it, and a narrow terminal truncates the ticker first. Both chips are dropped together when the session switches.

- [`1a6ccd3`](https://github.com/LIUTod/scream-code/commit/1a6ccd3a08fc0a4e9341813d68c4b59466223126) - Scheduled tasks now report back to the IM chat that owns the session. A cron fire runs inside the session with no inbound context, so its output used to finish invisibly: the driver now keeps one event subscription per live session and hands `cron.fired` to a `CronRelay`, which announces the fire (`⏰ 定时任务已触发：…`, the same copy the TUI status row uses), collects the turn's final text with `LineTurnCollector`, and delivers it through the new `sendProactive` path. Both channels send using the target they cached from inbound traffic — Lark keeps the chat id (`sendToChat`), WeChat keeps the peer and its `context_token` (`sendText`) — and both answer `sent` / `no-target` / `failed` instead of throwing, so a scheduled task can never crash the daemon. A fire that lands while a user turn is running is skipped, because `steer()` has already merged it into that turn and its reply reaches the chat anyway; one forward runs per session at a time. The same tasks can now be managed from the chat itself: `/cron` lists them, `/cron add <分 时 日 月 周> <要做的事>` creates one on the current session (so it belongs to that chat and reports back here), and `/cron rm <id>` deletes. A fired turn that ends without any text now reports `⚠️ 定时任务执行结束但没有输出：…` to the chat instead of finishing in silence, and tasks can be quiet too: `silent` skips the "fired" notice while still delivering the result, `mute` delivers nothing at all (both exposed through `CronCreate` and `/cron add --silent|--mute`), and each task remembers `lastError` from its latest run, shown in `/cron list` and cleared by the next clean run. Media sent from a scheduled turn now resolves through a platform-level sender fallback, so an image still goes out after `/stop`, `/cancel` or a restart. A guard drops a turn that never reports its end after 15 minutes so one stuck task cannot block later fires. WeChat still cannot push after a daemon restart until the user messages the bot once — that restriction is the platform's token model, and the log says so rather than failing silently.

- [`1a6ccd3`](https://github.com/LIUTod/scream-code/commit/1a6ccd3a08fc0a4e9341813d68c4b59466223126) - IM channels gain an interrupt and lose their silent gaps. `/stop` aborts the turn that is running right now via the new `LineSessionDriver.stopActiveTurn()` — the aborted turn suppresses its own reply so the chat is not told twice — and it is the one command that is not blocked while busy. A message that lands behind a running turn now answers immediately with `收到，前面还有 N 条在处理中。回复 /stop 可中止当前任务。` instead of waiting in silence. Voice support is probed once at startup (`ffmpeg -encoders`, looking for AMR-NB) and reported in `/status`, so a missing encoder is visible before the first fallback-to-file, and every submitted voice message logs that the gateway's `ret: 0` is not a delivery receipt — that log line is the only trace the platform gives. `/cancel` stops and starts a fresh session, and a `/stop` that cannot settle within 10 s closes the live session without deleting it, so the next message resumes the same session id — the same end result as tearing down the agent process. Shutdown now waits up to 60 s with a printed notice instead of cutting a turn after 10 s, the resolved `workDir` is printed at startup (warning when the config omits it), and daemon console lines carry ISO timestamps.

- [`04e67ab`](https://github.com/LIUTod/scream-code/commit/04e67abbad7de1578bd8bd53c650485ae2c52c9c) - A `/line` turn now gets an hour of wall-clock time instead of 15 minutes. Real work over chat — a full test run, a multi-file refactor, a long review — regularly passed the old cap and the user lost the whole turn; the new default is 60 minutes, configurable with `turnTimeoutMinutes` in `line/config.json` (1–1440). The cap is still only there so a turn that never settles cannot hold a chat's queue forever: when it does fire, the reply names the configured minutes instead of a hardcoded 15, `/status` shows the cap, the daemon prints it at startup, and scheduled-task turns are bounded by the same value rather than their own separate guard.

- [`e215b75`](https://github.com/LIUTod/scream-code/commit/e215b7596aa781b025b1a4d5ec55401b168b4e59) - The agent can now author a plugin for itself: write a plugin directory, `register_generated` it, then `activate` it to bring the new tool live. Registration accepts a manifest with a code entry point, which the manifest layer confines to the plugin directory and which still runs only on an explicitly approved `activate`. `/extension reload <id>` re-imports edited plugin code by dropping the cached module, so iterating on a self-authored plugin no longer needs a process restart. The format is documented in `docs/plugins.md` and indexed in the system prompt.

- [`041bc86`](https://github.com/LIUTod/scream-code/commit/041bc862d5aadca77bd04635e475f887f4f942c5) - The footer is now two fixed rows. Line 1 keeps identity: model name, provider balance and the working-tree git summary, with the context gauge right-aligned as `📨 Context：<bar> <percent>` (slim `▰▱` bar, 10/6/0 cells at >=68/>=52/<52 columns, floored with at least one lit cell for non-zero usage; the whole gauge shares one semantic colour). Line 2 starts with the cache hit rate, then the plan/rlm/wolfpack mode badges, the goal badge and background-task badges, with the channel readout `◆ Line: <Lark|Wechat|未连接> <work status>` right-aligned (only the dot is coloured; line 2 shrinks its left side first). The status row above the editor now uses one chip grammar: `⚠️ 重连中 n/max：reason · delay`, `🤝 name 求助：issue` / `✓ Scream 已处理 name 的请求`, and the idle hint in the theme's dim colour instead of a hardcoded grey.

  Subagent-to-parent collaboration requests no longer cut into the transcript. A delivered request surfaces as a one-line ticker above the editor — `coder is asking Scream for help: <preview>` — replaced by the newest event and echoed as `Scream handled the request from coder` once the main agent answers it. The request body stays in the parent's context and in the agent card's tool-call arguments. This removes the unreachable activity-pane component, the unused loader colour setter and the duplicate status-bar spinner branch, and stops the pulse-wave timer chain on shutdown.

### Patch Changes

- [`e53d2f9`](https://github.com/LIUTod/scream-code/commit/e53d2f9e9da0e2e7e8ea9141e8bc8fed847d4d8e) - Collapsed activity blocks now default to eight rows instead of three. At three rows a busy run only showed its header plus one step, which read as a frozen agent; the default now surfaces the newest steps of the timeline. `/blockrows` lets each user pick 5, 8 or 10, and a stored choice overrides the default; a previously stored 3 falls back to the new default.

- [`64b74b6`](https://github.com/LIUTod/scream-code/commit/64b74b6264f445b178d8f3bfa1e78198f1b58b8f) - `AGENTS.md` instructions are no longer lost silently. The merged prompt payload keeps a 32 KiB budget, but every discovered file now gets a 2 KiB floor first, so one oversized project guide can no longer zero the user-level `~/.scream-code/AGENTS.md` — the previous allocation order dropped those conventions from the prompt without a trace. A file that does not fit ends with `[... N bytes truncated; read <path> for the rest]`, so the model knows the guide continues and can open it, instead of assuming it read everything. Truncation itself is now a single encode plus a UTF-8 boundary walk rather than one character per pass, which removes a multi-second stall on the prompt path of every agent start and subagent spawn when the guide is large.

- [`ca795a1`](https://github.com/LIUTod/scream-code/commit/ca795a1a3e6dea6a1928e71d8bb4781ae85fa471) - Give `/config` an entry menu: a bare `/config` (or `/login`) now asks which configuration flow to enter — the shortcut provider directory, the custom DIY setup, or image generation — instead of jumping straight into the catalog. `/config diy` and `/config image` keep their direct paths, and the first-run nudge opens the same menu.

- [`49a3542`](https://github.com/LIUTod/scream-code/commit/49a3542835bbdd4a6043a346b9c1ad45369e698c) - Make the agent behave consistently on macOS, Linux and Windows. The bundled ripgrep binary is now picked by probing the host libc instead of inferring it from the CPU architecture, Windows falls back to PowerShell when Git Bash is absent, and command execution resolves `.cmd`/`.bat` shims through `PATHEXT` rather than relying on a shell. Timed-out hooks and update steps terminate the whole process tree on Windows. Path safety checks understand Windows drive letters and UNC paths, the external editor no longer assumes a POSIX shell, and installing the package no longer hard-fails on platforms without a prebuilt local-embedding binary. State files are located through the shared home resolver and written atomically.

- [`5290a2a`](https://github.com/LIUTod/scream-code/commit/5290a2a9d6ba94b51587fb4ad1478b335ce6924b) - Fix the embedding-model setup card reappearing on every startup on installs without a pre-existing model cache. The pinned model archive is now staged by the app itself from a first-party GitHub release with HTTP status validation and an on-disk sha256 check, instead of relying on the third-party model mirror that stopped serving anonymous downloads — its downloader never checks the response status, so a 403 error page used to be silently written into the staged archive and every subsequent extract failed. Lint ratchet baseline lowered to the new low.

- [`965f7df`](https://github.com/LIUTod/scream-code/commit/965f7df148bfe9c0d39bcb2756b22ebdd8f4df9f) - Send the product user agent with requests to third-party model endpoints. The identity used to be attached only to providers configured with a session header, so most OpenAI-compatible and Anthropic endpoints saw the SDK's own library user agent instead of the product's. Device fingerprint headers remain host-scoped and are not forwarded to third-party endpoints.

- [`74904e9`](https://github.com/LIUTod/scream-code/commit/74904e9f3832466a8f16d2e35e5b9568c36f35fc) - The status-bar pulse wave now reports network silence only. While the agent is waiting on the model but receiving nothing — a request awaiting its first token, a reasoning or text stream that stopped delivering, or a tool call whose arguments are still being authored — the wave ramps from the brand colour to yellow at 15s and to a deep red at 25s, then stays deep red. Any qualifying inbound event returns it to the brand colour immediately.

  Tool execution is exempt: a local command that prints nothing (`sleep`, a quiet install, a long test run) is still working, and its own timeout owns the outcome, so the wave keeps its brand colour for as long as the tool runs. The footer now distinguishes the two halves of a tool call — `调用中 / Calling` while the model streams the arguments, `执行中 / Running` while the tool executes.

  A retry floors the wave at yellow, so a known failure never renders next to a "reconnecting" label while the wave still claims everything is healthy. Child-agent traffic and non-stream custom tool notifications (such as an MCP OAuth prompt) no longer reset the parent's silence clock, so activity that does not belong to the main model stream cannot hide a stalled call. Switching sessions clears the work phase and the liveness clock, so a new session cannot inherit a stalled indicator.

  The wave uses dedicated palette tokens (`waveMid` yellow / `wavePeak` deep red) instead of the general warning/error colours, with a light-theme pair tuned for a white background. It remains an early warning only: retries still come from real transport failures (the stall timeout, disconnects, rate limits).

- [#18](https://github.com/LIUTod/scream-code/pull/18) [`2fda5b7`](https://github.com/LIUTod/scream-code/commit/2fda5b7ce50f060d09875a54f35f26e5fa7d8c58) - Recover explicit status codes from OpenAI-compatible streaming errors and classify status-less provider messages so transient failures enter the existing retry policy instead of immediately failing agent tasks.

- [`165a7ca`](https://github.com/LIUTod/scream-code/commit/165a7caa67c618fa82a6037d2cf0aa7da3c039b0) - Generated plan files no longer create a visible `plan/` folder in the project root when an agent has no session home: they now go to `.scream/plans`, which is already gitignored. The coverage report also moved out of the repository root to `node_modules/.cache/coverage`, so running the test suite no longer leaves a 27 MB `coverage/` directory behind.

- [`7f6bf0d`](https://github.com/LIUTod/scream-code/commit/7f6bf0d9b49026ced29de226884849add0a0ec32) - `/knowledge` can now ingest PDF, Word (.docx) and Excel (.xlsx) files alongside Markdown and plain text. Binary documents are converted to Markdown by the document engine that already ships with the runtime, then follow the exact same chunking and embedding path as a `.md` file, so the shared vector index and `/memory` are unaffected.

  Details:

  - The converter engine moved into the knowledge package (no new dependencies, no new package). It is imported lazily, so startup and `/memory` searches never pay for it.
  - Images are dropped and their placeholders stripped; a document with no text layer (scanned PDF) fails with a clear message instead of storing an empty record.
  - Documents are fingerprinted by their raw bytes, so an identical file is skipped and a changed one is re-ingested.
  - Directory ingestion skips hidden entries, Office lock files (`~$…`) and unsupported formats.
  - Ingest prompts now recommend Markdown first and warn that scans, image-heavy files and wide tables extract poorly.

- [`151b05d`](https://github.com/LIUTod/scream-code/commit/151b05d4f6feb4c316eb367fa546b6d4826ced79) - Replies now colour their two plainest marks, with one palette across both modes: `**bold**` picks up a new `mdBold` token and keeps SGR bold — violet, bright on dark (`#C9A0FF`, 7.9:1) and deep on light (`#6C2B8C`, 8.9:1) — and block quotes move to `mdQuote` for both the text and the `│` border — pink, bright on dark (`#FF6B9D`, 6.2:1) and deep on light (`#C2185B`, 5.9:1). Only brightness is tuned per mode, so emphasis always reads as the heavier mark and the hues never change meaning. Headings keep their amber: the renderer builds them as `heading(bold(text))`, so the heading now drops inherited styling before recolouring — without that, the coloured `bold` repainted every heading and replies looked randomly tinted. Table headers stay weight-only, the cli-highlight `quote` token inside fences stays neutral, and plain prose still carries no colour at all: it follows the terminal's own foreground.

- [`5e7d695`](https://github.com/LIUTod/scream-code/commit/5e7d69579bfcb07a28b2d425fcaa8697f29e0f3e) - MCP servers that advertise resources are now usable, not just their tools: `ListMcpResources`, `ListMcpResourceTemplates` and `ReadMcpResource` follow the naming and semantics other agents in this space converged on — `server` is optional and means "every connected server", listing returns JSON with each resource tagged by its server plus any `instructions` the server sent during the handshake, and reading reports the MIME type when a resource has no text content. They are read-only and only registered when MCP is configured. The MCP client also gained `listResourceTemplates()` and per-server `instructions`/`listPrompts()`.

  Server instructions now reach the model. They cannot live in the static system prompt — MCP connects asynchronously after the prompt is rendered, and rebuilding it later would invalidate the prompt-cache prefix — so the session injects them as one system reminder once the connections settle (a 250 ms window collapses a burst of connects), and only when the text changes. Delivery is retried when the main agent is created, without blocking agent creation on a slow server.

- [`0baa2ce`](https://github.com/LIUTod/scream-code/commit/0baa2ce006a5a611a2c16b1e02f163369a99108e) - Make /mcp uninstall honest for plugin-provided servers: the management panel now tags servers contributed by a plugin, refuses to "uninstall" them with a pointer to /plugin (that removal used to be undone on the next startup by the plugin hot-apply pass), and reports a real error instead of a fake success when a removed server is still listed.

- [`164e04b`](https://github.com/LIUTod/scream-code/commit/164e04b413618ef27ca4e9c81f69d7a9c50d6259) - Memory stays a single entity: `memos`. `/dream` merges near-duplicate memos and asks the model to write a distilled conclusion for each merge group, stored on the replacement memo as its latest distillation (最新归纳); merged memos also keep their sources' notes and a traceable lineage (`distilledFrom`, `distilledAt`, `origin`). Distilled rules are never age-pruned as resolved/stale, and a group that holds a rule is skipped when the plan carries no new conclusion. Both `distilled` and `note` are persisted, editable via `MemoryEdit` or in place from `/memory`, shown in `/memory` and memo injection, and returned by `MemoryLookup`; both also count towards keyword relevance, and search falls back to a LIKE match when a term appears only in either field.

  Each memo now also records where it came from: `origin` (`session` = extracted experience, `dream` = /dream rule, `user` = conclusion rewritten by the user), `distilledAt` (when the conclusion was generated or last rewritten) and `distilledFrom` (a snapshot of the memos folded into it — `{id, title, at}`, title clipped to 80 chars, max 100 items, carried across consolidation generations so a rule distilled from other rules keeps its ancestry). Existing rows are migrated in place: `origin` is backfilled to `dream` for every memo that already carries a `distilled` conclusion.

  The `/memory` picker shows rule provenance on the card (归纳 / 人工归纳, the distilled time and the source count) and in the detail view (归纳于 + up to five source entries, then `+N`), and lets the user rewrite the conclusion in place with `e` → Enter; a rewrite sets `origin='user'` and a fresh `distilledAt`, while clearing the text drops back to an extracted memo. Because merging permanently deletes the original memos, the `/dream` preview must show any existing conclusion it overrides, and deleting a rule in `/memory` now warns that its originals are gone for good.

- [`c45268a`](https://github.com/LIUTod/scream-code/commit/c45268a096ff2cb24849d0980d50cc4169e7a96a) - Plugin activation is per session. Two sessions can now run the same code plugin independently — each gets its own hooks, event subscriptions and tools — and stopping it in one leaves the other untouched. Before, activations were keyed by plugin id alone, so the second session could not activate a plugin the first already ran, while the plugin centre showed a single global "active" for every session. The status query and the stop call are now session-scoped; global paths (disable, remove, the capability-sync unwind) still take every copy down.

  The MCP client can also read a server's `instructions` and, when the server advertises the capability, list resources, list resource templates, read a resource and list prompt templates. (The user-facing surface for those is described in the MCP resource-tools entry.)

- [`a0714a0`](https://github.com/LIUTod/scream-code/commit/a0714a03bfdc61e2ff668bb824796e9280d433e9) - The TUI package moves from 1.1.0 to 1.5.0, which brings the upstream rendering fixes the local fork was missing: streaming Markdown re-renders only the block that changed instead of the whole document, bold/italic next to CJK punctuation renders, bare URLs stop at CJK punctuation, an unclosed `$$` block no longer swallows the table after it, deeply nested blockquotes no longer grow exponentially, HTML comments are no longer printed as body text, wide display math falls back to its source instead of being shredded across lines, the working indicator no longer disappears because of a stray terminal prompt marker, delayed terminal replies no longer leak into keyboard input, terminal modes are restored when the process exits without a clean stop, Kitty function keys and Shift+Enter are recognised, and more terminals are detected for images and hyperlinks.   On top of the port, four defects found in review are fixed: declaration files no longer ship `.ts` import specifiers (consumers either failed to compile or silently received `any`), narrow terminals no longer receive lines wider than their width when padding is set, the Markdown `tableHeader` option is honoured instead of silently ignored, and the spinner restyles after a theme change. - [`49a3542`](https://github.com/LIUTod/scream-code/commit/49a3542835bbdd4a6043a346b9c1ad45369e698c) - Stop reading injected reminders as a fresh user message when deciding whether to repeat the plan-mode reminder: only a real user prompt resets the cadence to the full reminder, so the periodic refresh threshold holds instead of re-emitting the long reminder on every step.

- [`c45268a`](https://github.com/LIUTod/scream-code/commit/c45268a096ff2cb24849d0980d50cc4169e7a96a) - Code plugins can now talk to the user instead of only adding tools. `context.ui` exposes three declarative primitives — `notify(level, message)`, `confirm({ title, body?, confirmLabel?, cancelLabel? })` and `progress(title)` with `update`/`done`/`fail` — all rendered by the host. A plugin therefore cannot wedge a session: `confirm` rides the same question channel the built-in ask tool uses and resolves `false` on a host that cannot ask, `notify` becomes a status message tagged `plugin:<level>`, and progress text is throttled to about five updates a second. - [`71379e3`](https://github.com/LIUTod/scream-code/commit/71379e35d8d184f1481312d97a5d5a674fb52c16) - Harden the runtime and close two discoverability gaps:

  - Dependency install scripts are denied by default (`onlyBuiltDependencies: []`), so a future dependency cannot silently run code at install time — the failure mode that once let a GPU download in an optional dependency break the vector feature.
  - Concurrent writes to the same file are serialized (per-path queue): parallel edits from one tool batch or from sibling sub-agents can no longer lose an update, while different files still write in parallel.
  - An abnormal exit is reported once on the next launch, pointing at `/sessions` to recover; clean exits and terminal hangups stay silent.
  - New `/hotkeys` (keyboard shortcut reference) and `/copy` (copy the last reply to the clipboard) commands.

- [`49a3542`](https://github.com/LIUTod/scream-code/commit/49a3542835bbdd4a6043a346b9c1ad45369e698c) - Stop appending a todo reconciliation round after the final answer: the reminder is now injected before the answer is written, inside the work the turn is already doing. - [`aa36f0e`](https://github.com/LIUTod/scream-code/commit/aa36f0e5757d301dd87b760373d6b68335d50bc5) - Tool output is now budgeted in bytes at whole-line granularity. The old builder capped 50 000 UTF-16 code units, so Chinese output silently consumed three times the intended budget, an emoji could be cut in half at the boundary, and a long line could be sliced mid-character. The head only ever holds complete lines; the tail window may start mid-line but always on a character boundary; an over-long single line keeps its own cap and says so.

  `read` stops promising something it could not do: the status block used to tell the model to re-read a long line with `n_lines=1`, which applied the same 2 KB cap. It now names the exact `bash sed -n '<line>p' … | head -c 65536` command.

  Also bounded: `Glob` output (50 KiB, with an omitted-paths count), subagent summaries (50 KiB, with a resume pointer), bash full-output artifacts (`0o600` and exclusive create instead of world-readable `/tmp` files), and the startup catalog refresh (24-hour freshness window plus `If-None-Match`, so a `304` no longer reparses and rewrites the snapshot).

- [`641f335`](https://github.com/LIUTod/scream-code/commit/641f3353706fb03a7eeadc8860fb5b27126042f8) - Move the local embedding engine off native binaries onto a self-contained WebAssembly pipeline. Installing no longer pulls a compiler toolchain or an unused GPU runtime on Linux (and can no longer lose the whole vector feature when that download fails), the dependency tree drops its deprecated packages, and the model download now reports byte progress with stall and overall timeout guards plus verify/load phases. A cache is only considered installed when the weights and both tokenizer files are present, so a half-restored cache repairs itself instead of failing at load time. - [`151b05d`](https://github.com/LIUTod/scream-code/commit/151b05d4f6feb4c316eb367fa546b6d4826ced79) - The status-bar pulse wave no longer reads a quiet tool call as a dead connection. It used to ramp from green to deep red after 25s of silence whenever the phase was not `执行中` — which caught the whole `调用中` window, so a long command being authored looked like a failure while it was fine. The wave now asks whether a tool call is actually in flight (`StreamingUIController.hasInFlightToolCalls()`, which counts argument previews as well as started calls) and keeps the brand colour for that call's entire lifetime, wherever the phase happens to be. A late argument preview can also no longer overwrite a call that already started, so a running command cannot regress to `调用中` and re-arm the ramp mid-execution. The silence ramp still covers the pure model phases (`等待响应` / `思考中` / `输出中`).
