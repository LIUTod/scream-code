Memories now come back on their own. Until now the agent wrote experience memos (at every compaction, on request, from unattended runs) but only read them when it thought to call `MemoryLookup` — which sat behind `DiscoverTools` and was called 0 times in 332 sessions, so 106 stored memos never reached a later conversation.

- **Recalled when it fits.** After each new request, the stored experience is compared with it by meaning (the local vector model) and a memo that clearly stands out — similarity at least 0.68 and well above the rest, near-copies dropped, at most three, this project first — is handed to the agent as a short `<memories>` note right after the request. It is framed as a hint to check against the code, not a fact; when it changes the plan the agent says so in a few words ("last time …, so this time …"), otherwise it stays silent. Most requests get nothing: on 1,241 real prompts it fired for 6.5% of them, one or two memos each (about 750 characters), and never for short replies like "继续". The note is appended after the request, so the prompt cache is untouched; the comparison runs locally in about 20 ms and costs no tokens.
- **Never a download, never for nothing.** The vector model is loaded only when it is already on disk and the project has memories to compare with (it takes a few hundred MB of memory once loaded). Without it nothing is recalled automatically and `MemoryLookup` still searches by keywords.
- **"How did we fix this last time" and "remember this" work at once.** `MemoryLookup` and `MemoryWrite` are always available to the agent; correcting and merging memories stay behind `DiscoverTools` (`memory` group, now with a hint for when). The memory part of the instructions is rewritten to match, shorter than before, and points standing preferences to `/like`.
- **Used memories count.** Every memo brought back, automatically or by a lookup, is counted; memos that keep helping rank higher in lookups, and the weekly self-review now sees how memories were used (added, recalled this week, never recalled for a month) so it can say which ones helped and propose tidying the rest. The counters are bookkeeping: editing a memo keeps them, and the change history does not record a recall as a change.
- You see it happen: a dim line under your message — "· 已参考 2 条以往经验" — nothing to do, it only says Scream drew on them; `/memory` shows how often each memory was recalled and when last.
- Recalled notes are not stored again as new experience: compaction is told to skip them and exit extraction leaves them out.
- **It knows what it knows.** With the first message of a conversation the agent gets a short note — how many experiences it remembers and their most frequent topics (about a hundred tokens, once per conversation) — so a broad question ("what should I watch out for building an agent CLI?"), which no single memory matches closely enough to be recalled, still makes it look in its memories before answering from general knowledge. Advice and design questions about your own work are now answered after checking memories, the code and its history, saying what was checked.
- **"This project" is judged by folder, loosely.** Memories made in a subfolder of a repo, or in the home folder a session was started in, count for the project; before, a session opened at the repo root found none of them and never loaded the vector model (102 of 106 real memories were made in the home folder).
- **Tools enabled through `DiscoverTools` work right away.** They used to become callable only from the next message — the tool itself said "available from your next turn" — so a model that enabled the knowledge library could not use it in that answer and skipped it. They are now offered from the next step of the same turn, a direct call to a tool of a not-yet-enabled group enables the group on the spot (also within one batch of calls), and the enabled groups are written to the session so a resumed session keeps them.
