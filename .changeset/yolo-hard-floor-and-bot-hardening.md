yolo, the startup default, keeps a hard floor. A new `yolo-hard-floor-ask` policy, placed directly above `yolo-mode-approve`, still asks in yolo for the operations whose damage outlives the session and that an injected instruction alone can trigger, all once-only except the first: sending data to a non-allowlisted host after the session read private data outside the workspace (same assessment, allowlist and session grant as `private-read-egress-ask`; once or session); git control data — any write under a `.git` directory or to `~/.gitconfig`, or a Bash command that may write hooks or a git config key git later runs as a command (`core.hooksPath`, `core.fsmonitor`, `core.pager`, `core.sshCommand`, `core.editor`, `credential.helper`, filter/merge drivers, `!` aliases); shell startup files (`~/.zshrc`, `~/.bashrc`, `~/.bash_logout`, fish `conf.d` …); and other startup persistence (`~/.ssh/authorized_keys` / `rc` / `config`, LaunchAgents / LaunchDaemons, systemd user units, autostart entries, installing a crontab). Every other yolo call is still approved without a prompt.

The Bash side is a best-effort text heuristic, and it is gated the safe way round: a command that names one of those targets passes only if every segment is a command known to read (`cat`, `grep`, `ls`, `git status` / `log` / `diff`, `git config --get`, `crontab -l`, `find` without `-exec`/`-delete` …); anything else asks, so a writer nobody listed (`curl -o`, `wget -O`, `python -c`, `awk -i inplace`) is stopped by default. `git` is recognised through its global options (`git -C dir config …`, `git -c k=v config …`, `--no-pager`), and a nested `$(…)` / backtick command counts as a possible write. A path assembled at run time can still evade it. Headless `-p` and LINE sessions auto-approve every prompt, so the floor does not stop them there; stream-json forwards the prompt to its client.

bot mode no longer auto-approves writes where code runs later, outside bot mode: `.husky` / `.githooks`, CI definitions (`.github`, `.gitlab`, `.circleci`, `.buildkite`, `.gitlab-ci.yml`, `azure-pipelines.yml`, `Jenkinsfile`), `.pre-commit-config.yaml` / lefthook, `.vscode` / `.idea` / `.devcontainer`, and `.envrc`. Cross-session memory writes (`MemoryWrite`, `MemoryEdit`, `MemoryConsolidateApply`) are denied in bot mode, because a memo is injected into later sessions; memory lookups still run.

MCP: a cancelled browser authorization whose failure arrives late no longer deletes the newer flow's pending slot, which let a third `/mcp` authenticate start a concurrent flow and invalidate the URL the user had open.
