MCP servers that advertise resources are now usable, not just their tools: `ListMcpResources`, `ListMcpResourceTemplates` and `ReadMcpResource` follow the naming and semantics other agents in this space converged on — `server` is optional and means "every connected server", listing returns JSON with each resource tagged by its server plus any `instructions` the server sent during the handshake, and reading reports the MIME type when a resource has no text content. They are read-only — classified as such in the tool catalog, so manual mode does not prompt for them and restricted subagents are not denied at call time. The MCP client also gained `listResourceTemplates()` and per-server `instructions`/`listPrompts()`.

Server instructions now reach the model. They cannot live in the static system prompt — MCP connects asynchronously after the prompt is rendered, and rebuilding it later would invalidate the prompt-cache prefix — so the session injects them as one `<mcp-server-instructions>` block once the connections settle (a 250 ms window collapses a burst of connects), and only when the text changes. The block arrives as a user-role message rather than a system reminder: its text comes from the server, and the prompt treats such blocks as workflow guidance that cannot grant permissions, approve actions, or stand in for the user's consent. Delivery is retried when the main agent is created, without blocking on a slow server; resume seeds the dedup state from the replayed history so repeated resumes do not append the same block again.
