Scheduled tasks now report back to the IM chat that owns the session. A cron fire runs inside the session with no inbound context, so its output used to finish invisibly: the driver now keeps one event subscription per live session and hands `cron.fired` to a `CronRelay`, which announces the fire (`⏰ 定时任务已触发：…`, the same copy the TUI status row uses), collects the turn's final text with `LineTurnCollector`, and delivers it through the new `sendProactive` path. Both channels send using the target they cached from inbound traffic — Lark keeps the chat id (`sendToChat`), WeChat keeps the peer and its `context_token` (`sendText`) — and both answer `sent` / `no-target` / `failed` instead of throwing, so a scheduled task can never crash the daemon. A fire that lands while a user turn is running is skipped, because `steer()` has already merged it into that turn and its reply reaches the chat anyway; one forward runs per session at a time. The same tasks can now be managed from the chat itself: `/cron` lists them, `/cron add <分 时 日 月 周> <要做的事>` creates one on the current session (so it belongs to that chat and reports back here), and `/cron rm <id>` deletes. A fired turn that ends without any text now reports `⚠️ 定时任务执行结束但没有输出：…` to the chat instead of finishing in silence, and tasks can be quiet too: `silent` skips the "fired" notice while still delivering the result, `mute` delivers nothing at all (both exposed through `CronCreate` and `/cron add --silent|--mute`), and each task remembers `lastError` from its latest run, shown in `/cron list` and cleared by the next clean run. Media sent from a scheduled turn now resolves through a platform-level sender fallback, so an image still goes out after `/stop`, `/cancel` or a restart. A guard drops a turn that never reports its end after 15 minutes so one stuck task cannot block later fires. WeChat still cannot push after a daemon restart until the user messages the bot once — that restriction is the platform's token model, and the log says so rather than failing silently.
